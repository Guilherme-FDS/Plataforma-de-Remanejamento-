# 2026-09-15 — Correções, restrição de visualizador, reorganização, novo lote de pedidos

Terceiro dia: começou testando a gestão de usuários criada no dia
anterior, apareceram dois bugs de banco, depois foi pedido um lote grande
de melhorias novas.

## Bugs encontrados e corrigidos

- [x] **Recursão infinita na RLS de `perfis`**. A policy `perfil_admin`
      (desde `0001_schema.sql`) fazia uma subconsulta na própria tabela
      `perfis` dentro do `USING` — qualquer leitura de perfis reavaliava a
      RLS, que reavaliava de novo, em loop. Efeito prático: `perfilAtual()`
      e `verificarAdmin()` engoliam o erro e devolviam `null` — usuário
      sem nome, sem botão Sair, e "Requer perfil de administrador" mesmo
      sendo admin. Corrigido com uma função `sou_admin()`
      `SECURITY DEFINER` (`ee9311e`, migration `0007`).
- [x] **Ordem errada na migration multi-unidade**. A função
      `minha_unidade_id()` era criada antes da coluna
      `perfis.unidade_id` existir — funções `language sql` validam o
      corpo na criação, então a migration falhava com
      `column "unidade_id" does not exist`. Corrigido invertendo a ordem
      (`1685971`).
- [x] Migration `0006_multi_unidade.sql` executada com sucesso no banco
      de produção (ação manual no SQL Editor do Supabase, após a
      correção de ordem acima).

## Restrição de visualizador

Pedido: visualizador não pode ver a aba Configurações, não pode encerrar,
editar nem criar novos casos.

- [x] `verificarOperador()` (em `actions/remanejamentos.ts` e
      `actions/admin.ts`) virou **fail-safe**: antes só bloqueava quando o
      papel lido era exatamente `"visualizador"` — se a leitura do perfil
      falhasse (como no bug de recursão acima) o código **liberava** por
      engano. Agora só libera quem é explicitamente `"operador"`.
- [x] Nav esconde "Config." e "Novo lançamento" para visualizador
- [x] Lista de casos esconde "Editar" e "Encerrar" para visualizador
- [x] Páginas `/remanejamentos/novo`, `/remanejamentos/[id]/editar` e
      `/admin` redirecionam visualizador que tentar acessar direto pela
      URL
- [x] (`eb9062a`)

## Correções depois dos primeiros testes

- [x] **Produção fora do ar**: a view `vw_remanejamentos` usa `select r.*`,
      e o PostgreSQL congela a expansão do `*` na criação da view. A coluna
      `excluido` (0008) nunca chegou na view. Erro de análise minha ao
      escrever a 0008 — corrigido na migration `0010`, que recria a view.
- [x] **Security Advisor do Supabase**: migration `0009` fixa o
      `search_path` de duas funções e tira as funções de trigger e as
      helpers de RLS do alcance de `anon`. Os avisos sobre `authenticated`
      poder executar as helpers ficam de propósito — é assim que a RLS
      funciona.
- [x] **Seletor de unidade não trocava o contexto**: ele definia só onde o
      lançamento era gravado; a leitura continuava vindo de todas as
      unidades somadas (a RLS libera todas para quem tem alcance "todas").
      Trocar para Paranavaí mostrava os dados de Maringá. Agora
      `unidadeAtivaLeitura()` filtra casos, colaboradores, ficha, histórico
      e todas as listas. O seletor ganhou a opção "Todas as unidades" e
      passou a aparecer no celular.
- [x] **Nomes repetidos entre unidades quebrariam o lançamento**: as buscas
      de setor/turno/segmento/supervisor/profissional por nome, e a de
      colaborador por matrícula, não filtravam por unidade — com duas
      unidades em uso o `maybeSingle()` acharia duas linhas e falharia.
      Corrigido antes de aparecer em produção.
- [x] **Caso excluído continuava na ficha do colaborador** — o soft delete
      tirava das listas, mas `historicoDoColaborador` não filtrava.

## Perfil e Pendências

- [x] **Modal com os próprios dados** ao clicar no nome no topo da tela —
      nome, e-mail, função, papel, se é administrador, unidade e alcance de
      unidades. Funciona para qualquer papel, inclusive visualizador (que

  - Nova seção **"Precisa de correção"**, calculada na hora a partir dos
    casos vigentes. Quatro regras definidas pelo usuário: sem matrícula ·
    sem duração/previsão · segmento não classificado · tipo indefinido.
    Por ser calculada, some sozinha quando o campo é preenchido — não
    existe pendência resolvida presa na lista.
  - Cada item linka para a ficha do colaborador e tem botão **"Corrigir"**
    (lançador/operador) indo direto para a edição do caso.
  - Seção **"Da importação inicial"** ganhou botão **"Marcar resolvida"**,
    usando as colunas `resolvida`/`resolvida_por`/`resolvida_em` que
    existiam sem uso desde a `0003`. Dá para reabrir.
  - Só considera casos **em aberto**: caso encerrado com dado incompleto é
    histórico, não trabalho a fazer.
  - Limitação assumida: a tabela da importação guarda o colaborador como
    texto livre, sem vínculo com o cadastro. O link só aparece quando o
    nome bate com alguém cadastrado.
