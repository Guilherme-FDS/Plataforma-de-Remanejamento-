# 2026-09-15 — Correções, restrição de visualizador, reorganização, novo lote de pedidos

Terceiro dia: começou testando a gestão de usuários criada no dia
anterior, apareceram dois bugs de banco, depois foi pedido um lote grande
de melhorias novas.

## Bugs encontrados e corrigidos

- [x] **Recursão infinita na RLS de `perfis`**. A policy `perfil_admin`
      (desde `0001_schema.sql`) fazia uma subconsulta na própria tabela
      `perfis` dentro do `USING` — qualquer leitura de perfis reavaliava a
      RLS, que reavaliava de novo, em loop. Efeito prático: `perfilAtual()`
      e `verificarAdmin()` engoliam o erro e devolviam `null` — usuário
      sem nome, sem botão Sair, e "Requer perfil de administrador" mesmo
      sendo admin. Corrigido com uma função `sou_admin()`
      `SECURITY DEFINER` (`ee9311e`, migration `0007`).
- [x] **Ordem errada na migration multi-unidade**. A função
      `minha_unidade_id()` era criada antes da coluna
      `perfis.unidade_id` existir — funções `language sql` validam o
      corpo na criação, então a migration falhava com
      `column "unidade_id" does not exist`. Corrigido invertendo a ordem
      (`1685971`).
- [x] Migration `0006_multi_unidade.sql` executada com sucesso no banco
      de produção (ação manual no SQL Editor do Supabase, após a
      correção de ordem acima).

## Restrição de visualizador

Pedido: visualizador não pode ver a aba Configurações, não pode encerrar,
editar nem criar novos casos.

- [x] `verificarOperador()` (em `actions/remanejamentos.ts` e
      `actions/admin.ts`) virou **fail-safe**: antes só bloqueava quando o
      papel lido era exatamente `"visualizador"` — se a leitura do perfil
      falhasse (como no bug de recursão acima) o código **liberava** por
      engano. Agora só libera quem é explicitamente `"operador"`.
- [x] Nav esconde "Config." e "Novo lançamento" para visualizador
- [x] Lista de casos esconde "Editar" e "Encerrar" para visualizador
- [x] Páginas `/remanejamentos/novo`, `/remanejamentos/[id]/editar` e
      `/admin` redirecionam visualizador que tentar acessar direto pela
      URL
- [x] (`eb9062a`)

## Novo lote de pedidos — analisado, aprovado e implementado

> Regra combinada a partir de agora: antes de qualquer implementação, um
> checklist é apresentado e só se começa após o "ok" do usuário. Este lote
> foi aprovado com "todas as coisas... implemente tudo".

- [x] **Exportar XLSX** em vez de CSV nos relatórios (biblioteca `xlsx`,
      carregada sob demanda só quando alguém exporta)
- [x] **PDF em aba nova**: nova rota `/relatorios/imprimir` — server
      component sem Nav, só cabeçalho + tabela filtrada, aberta em nova
      aba e com impressão disparada automaticamente
      (`components/AutoPrint.tsx`)
- [x] **Excluir lançamento** — soft delete (`remanejamentos.excluido`,
      `excluido_em`, `excluido_por`), botão na lista de Casos, tela
      "Excluídos" com opção de restaurar. Permissão: só operador.
- [x] **Modal ao clicar em usuário** em Configurações → Usuários — mostra
      nome, e-mail, função, papel, unidade, alcance de unidades, unidades
      extras, admin, status e último acesso
- [x] **Hierarquia de acesso mais granular** — implementada com dois eixos
      independentes:
  - **Papel** (o que a pessoa pode fazer): `visualizador` | `lancador`
    (cria/edita, não exclui — pedido "no futuro" virou "agora") |
    `operador` (cria, edita e exclui)
  - **Alcance de unidades** (o que a pessoa enxerga): `propria` | `todas`
    (gestor) | `especificas` (a própria + as liberadas pelo admin,
    guardadas em `perfil_unidades_extra`)
  - Configurável na tela de usuário, em Configurações — continua
    inacessível para visualizador
- [x] **Unidades funcionando**: nova aba "Unidades" em Configurações
      (criar, renomear, ativar/desativar — nasce vazia, confirmado com o
      usuário), seletor de "unidade ativa" no menu para quem enxerga mais
      de uma unidade, e todas as escritas (lançar caso, criar item de
      lista) passam a gravar na unidade ativa validada, não mais só na
      unidade de casa
- [x] Migration `0008_hierarquia_e_exclusao.sql` — schema completo dessas
      mudanças (ver [[Manual-Tecnico]] para detalhe técnico)
